# 縱谷自由行動所（VALLEY FREEDOM）設計規格

日期：2026-10-16

## 目標與範圍

建立一個可用於地方創生競賽展示的響應式網站原型，呈現旅客自由組合地方微體驗，以及木日光、在地業者與青年共同開發服務的營運流程。主要場域為花蓮瑞穗木日光文旦驛站及花東縱谷。所有介面以繁體中文為主。

原型使用 React、TypeScript、Vite、Tailwind CSS、React Router、Lucide React 與 LocalStorage。使用示意資料，不連接真實帳號、金流、地圖 API、資料庫或即時多人服務。LocalStorage 僅代表目前瀏覽器中的展示資料。

## 使用者與資訊架構

全站共用頂部品牌導覽、頁尾、示意資料標記及角色切換器。角色切換器提供旅客、青年、業者三種展示視角，不代表真實身分驗證或安全權限。頁面以 React Router 導覽，手機導覽需可觸控操作且不產生內層捲軸。

- 公開旅客頁：首頁、探索體驗、體驗詳情、自由旅程組合器、我的預約、木日光介紹。
- 青年工作台：任務列表與詳情、申請任務、我的申請、已接受任務、完成紀錄與示意報酬/工時統計。
- 業者後台：營運摘要、體驗與場次管理、預約訂單審核、青年任務與排班管理、示意營收與合作成果。
- 共創模組：地方資源盤點、體驗草案、試辦場次、回饋評估、修改紀錄、正式上架。
- 全站提供重置示範資料入口；執行前需二次確認。

## 核心流程

### 旅客探索與預約

至少 8 筆類型不同的示意體驗，涵蓋文旦食農、地方飲食、手作技藝、聚落故事、自然觀察、場域體驗等。探索頁可依類別、日期、價格、時長、關鍵字和可預約狀態篩選。體驗詳情顯示介紹、圖片、地點、集合資訊、時長、價格、場次時間與即時剩餘名額。旅客選擇場次、人數後可模擬送出預約，並於我的預約查看待確認、已確認、已取消或已完成狀態。

待確認及已確認訂單占用名額；已取消訂單不占用名額。送出預約時以同一狀態操作檢查剩餘名額，禁止超額。取消需確認，取消後釋出名額；不得重複取消，也不得直接取消已完成訂單。旅客取消及業者取消共用同一核心操作函式，記錄取消原因、操作來源及時間。業者確認或取消訂單後，旅客端讀取同一筆資料並顯示同步狀態。所有訂單、體驗、場次均使用穩定唯一 ID。

### 自由旅程

旅客可選日期、預算、興趣類別和可用時間，加入正式體驗或自行建立的自由活動。清單可新增、移除、排序及儲存；畫面計算體驗費用和預算差額，並檢查體驗時段衝突。自由活動不使用業者場次名額。加入行程只更新行程草稿，不建立預約。畫面分開呈現草稿項目與實際預約，且已取消訂單維持已取消標示，不被當成有效預約。行程使用獨立 ID 並存入 LocalStorage。

### 青年任務

青年可檢視任務內容、日期時段、需求條件、工作內容與示意報酬，並提出申請。相同青年不可重複申請同一任務。業者可審核申請與管理錄取名額。狀態包含待審核、已錄取、未錄取、已完成、已取消；青年與業者頁面顯示同一筆申請狀態。僅符合條件且標記完成的任務計入工時與報酬統計。任務工作不包含未具資格者承接受法規限制的導遊、交通接送或水域活動。

### 體驗共創

共創生命週期依序為資源盤點、體驗草案、試辦、回饋評估、正式上架。資源可用人、空間、技術、商品、文化、故事、關係、閒置資源分類。草案不出現在公開正式體驗列表；試辦場次明確標示「試辦」，不可進入一般正式預約。收集示意參與者回饋，保留回饋與修改紀錄。只有正式上架後建立正式體驗，才可進入旅客預約流程。正式體驗保留原始草案 ID，並有自己的正式體驗 ID，以便追溯地方資源、試辦、回饋、修改與最終商品。每一資源、草案、場次、回饋與修改紀錄均有唯一 ID。

## 資料與狀態管理

建立一個集中式 TypeScript 領域模型與狀態管理模組，統一讀寫 LocalStorage。資料包含體驗、場次、預約、行程、旅客/青年展示識別、任務、任務申請、地方資源、共創草案、試辦場次、回饋及修改紀錄。所有修改只能透過集中管理函式執行；頁面元件不得直接寫 LocalStorage。初次載入時以版本化示意資料初始化，重新整理與跨頁導覽後資料一致。以 `storage` 事件監聽同瀏覽器其他分頁的資料變更並更新畫面。LocalStorage 與分頁同步不提供真正並行交易保證，介面需明示此原型限制。所有 ID 穩定且唯一。操作函式負責狀態轉移、輸入檢查、名額計算、防重複申請與完成工時計算，並提供可顯示給使用者的成功或失敗結果。

名額剩餘量由場次容量減去同一場次所有待確認及已確認訂單人數計算，不另存一份容易過期的可用數量。單一分頁操作在同一次狀態更新內檢查並保存；跨分頁透過 `storage` 事件更新畫面，但不保證並行預約的原子性或交易隔離。重置操作二次確認後恢復初始示意資料。

## 頁面視覺與互動

美術方向結合自然童話感的植物/地方插畫、細膩藝術字體與日系編輯式版面，插畫保持成熟、精緻且不遮蔽資訊。網站仍需以真實場域感、清晰閱讀層次、合理留白、柔和邊框與穩定導覽為優先。採用奶油白 #F8F6F0、鼠尾草綠 #A7B9A2、森林綠 #284B3B、暖米色 #E8E0D2、深灰 #292D29。中文使用 Noto Sans TC 系統字體堆疊，英文標題搭配優雅 Serif。禁止 Emoji；只少量使用 Lucide 線條圖示。不可使用花俏漸層、螢光色、低對比導覽、擁擠卡片、裁切文字或無功能按鈕。手機與桌面皆需完整適配，支援鍵盤焦點及減少動態效果偏好。

每個新增、修改、刪除、確認或取消操作應呈現明確結果；重要操作需確認。提供無資料、錯誤、無可用名額和超出預算/時段衝突等清楚狀態與可採取的下一步。活動、價格、營運數據均明示為示意資料。

## 驗收條件

1. 旅客可探索篩選至少 8 種示意體驗、查看詳情、選擇場次與人數、送出模擬預約並查看紀錄。
2. 待確認和已確認訂單占用名額；取消釋放名額；超額、重複取消及取消已完成訂單被阻止；業者狀態變更即時反映於同一瀏覽器其他頁面。
3. 行程可新增/移除/排序/儲存，正確提示衝突與預算差額；自由活動不占場次名額；加進行程不會新增預約。
4. 青年可申請任務；重複申請受阻；業者審核/完成狀態同步；只有合格完成任務進入工時統計。
5. 共創可依序完成資源、草案、試辦、回饋及正式上架；草案和試辦不進正式探索與一般預約。
6. 切換角色、重新整理及跨頁導覽後保留一致資料；唯一 ID 可追溯各紀錄；重置須二次確認並恢復初始資料。
7. 桌面與手機版主要流程可操作；按鈕具實際功能；操作回饋、空狀態與錯誤提示清楚。
8. 驗收清單需涵蓋旅客、青年、業者三種角色的主要流程。

## 非目標

真實登入與權限控制、多人雲端即時同步、金流、外部地圖服務、真實預約通知或實際營運資料均不在此原型範圍。
